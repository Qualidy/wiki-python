    OOP Wiederholung¶

    Bevor neue OOP-Themen dazukommen, werden die Grundlagen wiederholt. Ziel ist, Klassen nicht nur schreiben, sondern auch in fremdem Code sicher erkennen zu können.

    Klasse und Objekt¶

    Eine Klasse ist ein Bauplan. Ein Objekt ist ein konkretes Exemplar dieses Bauplans.

    Methoden und self¶

    Methoden sind Funktionen, die zu einer Klasse gehören. Der erste Parameter einer Instanzmethode heißt per Konvention self.

     1

    class Person:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        return f"Hallo, ich bin {self.name}."


person = Person("Ada")
print(person.introduce())

    self ist das Objekt, auf dem die Methode gerade aufgerufen wurde.

    Kapselung¶

    Kapselung bedeutet, dass Daten und Verhalten zusammen in einer Klasse liegen. Python nutzt dafür Konventionen:

    class Account:
    def __init__(self, owner, balance):
        self.owner = owner
        self.__balance = balance

    def deposit(self, amount):
        self.__balance += amount

    def get_balance(self):
        return self.__balance

    Vererbung und super()¶

    class Vehicle:
    def __init__(self, brand):
        self.brand = brand

    def start(self):
        return f"{self.brand} startet."


class Car(Vehicle):
    def __init__(self, brand, doors):
        super().__init__(brand)
        self.doors = doors

    super().__init__(brand) ruft den Konstruktor der nächsten Klasse in der Vererbungskette auf.

    🌶 OOP-Wiederholungsquiz

    Beantworte die Fragen kurz:

    1. Was ist der Unterschied zwischen Klasse und Objekt?
    2. Was ist ein Instanzattribut?
    3. Was ist ein Klassenattribut?
    4. Wofür steht self?
    5. Wann wird __init__ ausgeführt?
    6. Was bedeutet Overriding?
    7. Was ist der Unterschied zwischen is und ==?
    8. Warum ist isinstance() bei Vererbung oft sinnvoller als type()?
    Lösung

    Mögliche Antworten:

    1. Eine Klasse ist ein Bauplan, ein Objekt ist ein konkretes Exemplar.
    2. Ein Instanzattribut gehört zu einem bestimmten Objekt.
    3. Ein Klassenattribut gehört zur Klasse und ist über alle Instanzen erreichbar.
    4. self referenziert das Objekt, auf dem die Methode aufgerufen wurde.
    5. __init__ wird nach dem Erzeugen einer neuen Instanz ausgeführt.
    6. Overriding bedeutet, dass eine Unterklasse eine Methode der Oberklasse neu definiert.
    7. is prüft Identität, == prüft Gleichheit.
    8. isinstance() berücksichtigt auch Oberklassen.

    🌶🌶 Bankkonto mit Kapselung

    Implementiere eine Klasse BankAccount.

    Anforderungen:

    • Konstruktor mit owner und balance
    • balance soll intern als __balance gespeichert werden
    • Methode deposit(amount)
    • Methode withdraw(amount)
    • Methode get_balance()
    • bei negativen Beträgen soll ValueError geworfen werden
    • bei zu hoher Auszahlung soll ebenfalls ValueError geworfen werden
    • __str__ soll z.B. Konto von Ada: 120 Euro zurückgeben

    class BankAccount:
    def __init__(self, owner, balance):
        if balance < 0:
            raise ValueError("Startguthaben darf nicht negativ sein.")
        self.owner = owner
        self.__balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Betrag muss positiv sein.")
        self.__balance += amount

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("Betrag muss positiv sein.")
        if amount > self.__balance:
            raise ValueError("Nicht genug Guthaben.")
        self.__balance -= amount

    def get_balance(self):
        return self.__balance

    def __str__(self):
        return f"Konto von {self.owner}: {self.__balance} Euro"

    class Student:
    def __init__(self, name, email):
        self.name = name
        self.email = email

    def __str__(self):
        return f"{self.name} <{self.email}>"


class Course:
    def __init__(self, title):
        self.title = title
        self.students = []

    def add_student(self, student):
        if not isinstance(student, Student):
            raise TypeError("Es können nur Student-Objekte hinzugefügt werden.")
        self.students.append(student)

    def __len__(self):
        return len(self.students)

    def __str__(self):
        return f"{self.title}: {len(self)} Teilnehmer"


course = Course("Python OOP")
course.add_student(Student("Ada", "ada@example.com"))
course.add_student(Student("Linus", "linus@example.com"))

print(course)
print(course.students[0])

    class Product:
    def __init__(self, name, price, stock):
        if price < 0 or stock < 0:
            raise ValueError("Preis und Bestand dürfen nicht negativ sein.")
        self.name = name
        self.price = price
        self._stock = stock

    def sell(self, amount):
        if amount <= 0:
            raise ValueError("Menge muss positiv sein.")
        if amount > self._stock:
            raise ValueError("Nicht genug Bestand.")
        self._stock -= amount

    def restock(self, amount):
        if amount <= 0:
            raise ValueError("Menge muss positiv sein.")
        self._stock += amount

    def __str__(self):
        return f"{self.name}: {self.price} Euro, Bestand: {self._stock}"
    🌶🌶🌶 Eigene Exception-Klasse: Lagerbestand

    Implementiere eine kleine Lagerklasse mit eigener Exception.

    Anforderungen:

    • Erstelle eine eigene Exception-Klasse OutOfStockError.
    • Erstelle eine Klasse Product mit:
    • name
    • _stock
    • Methode sell(amount)
    • Methode restock(amount)
    • Methode get_stock()
    • sell(amount) soll eine OutOfStockError werfen, wenn mehr verkauft werden soll, als vorhanden ist.
    • Bei amount <= 0 soll eine ValueError geworfen werden.
    • Schreibe einen kurzen Demo-Ablauf mit try/except, der beide Fehlerarten zeigt.

    Zusatz:

    • Gib der Exception eine sinnvolle Fehlermeldung, z.B. mit Produktname, gewünschter Menge und verfügbarem Bestand.
    • Prüfe mit isinstance(error, Exception), ob deine eigene Exception von Exception erbt.
    Tipp

    Eine eigene Exception ist meistens eine sehr kleine Klasse, die von Exception erbt. Wichtig ist hier nicht viel Code, sondern dass dein Programm fachlich unterscheiden kann: ungültige Menge ist ValueError, zu wenig Bestand ist OutOfStockError.

    🌶🌶🌶 Class Properties mit @property: Temperatur

    Implementiere eine Klasse TemperatureReading, die mit Properties arbeitet.

    Anforderungen:

    • Konstruktor mit sensor_id und celsius.
    • Speichere den Celsius-Wert intern als _celsius.
    • Erstelle eine Property celsius.
    • Erstelle einen Setter für celsius.
    • Der Setter soll prüfen:
    • Wert muss int oder float sein.
    • Wert darf nicht kleiner als -273.15 sein.
    • Bei ungültigem Typ soll TypeError geworfen werden.
    • Bei zu niedrigem Wert soll ValueError geworfen werden.
    • Erstelle eine read-only Property fahrenheit, die aus celsius berechnet wird.
    • __str__ soll eine lesbare Ausgabe liefern, z.B. Sensor A1: 21.5 C / 70.7 F.

    Schreibe danach einen kurzen Demo-Ablauf:

    • Objekt erzeugen
    • celsius lesen
    • fahrenheit lesen
    • celsius über die Property ändern
    • einen ungültigen Wert testen und Fehler abfangen

    Zusatz:

    • Erkläre in 2-3 Sätzen, warum fahrenheit keine eigene Instanzvariable sein muss.
    • Prüfe mit reading.__dict__, welche Attribute wirklich gespeichert sind.
    Tipp

    Eine Property sieht beim Verwenden wie ein Attribut aus, ruft intern aber Methoden auf. Dadurch kannst du Validierung einbauen, ohne dass Nutzer der Klasse get_celsius() oder set_celsius() aufrufen müssen.
