    Projekt dokumentieren mit Markdown¶

    Zu einem Softwareprojekt gehört nicht nur Code. Andere Personen müssen verstehen, was das Projekt macht, wie man es startet und wie der Code grob aufgebaut ist.

    Dafür wird häufig eine Datei namens README.md verwendet. Die Endung .md steht für Markdown.

    Was ist Markdown?¶

    Markdown ist eine einfache Schreibweise für formatierte Texte. Man schreibt normalen Text und ergänzt wenige Zeichen für Überschriften, Listen, Links, Codeblöcke und Tabellen.

    Markdown wird zum Beispiel verwendet in:

    • GitHub-Repositories
    • technischen Dokumentationen
    • Projektbeschreibungen
    • Aufgabenblättern
    • Wikis und Lernmaterialien

    Was gehört in eine README?¶

    Eine gute Projekt-Dokumentation beantwortet mindestens diese Fragen:

    Abschnitt Frage
    Projektname Wie heißt das Projekt?
    Kurzbeschreibung Was macht das Programm?
    Features Was kann das Programm?
    Installation Was muss vorher installiert werden?
    Start Wie führt man das Programm aus?
    Bedienung Wie benutzt man es?
    Projektstruktur Welche Dateien sind wichtig?
    Beispiele Wie sieht eine typische Nutzung aus?
    Bekannte Grenzen Was funktioniert noch nicht?
    Ausblick Was könnte man verbessern?

    Codeblock in Codeblock

    Wenn du eine Markdown-Vorlage zeigst, die selbst Codeblöcke enthält, brauchst du außen mehr Backticks als innen. Deshalb wurde oben außen ein längerer Markdown-Codeblock verwendet.

    Mini-Präsentation¶

    Für die Vorstellung eines Projekts reicht oft eine klare Struktur:

    1. Was war die Idee?
    2. Was kann das Programm?
    3. Welche Datei ist der Einstiegspunkt?
    4. Welche Stelle im Code ist besonders wichtig?
    5. Was war schwierig?
    6. Was würdest du als Nächstes verbessern?
    🌶 README zum letzten Projekt

    Erstelle für dein Projekt der letzten Woche eine Datei README.md.

    Die README soll mindestens diese Abschnitte enthalten:

    • Projektname
    • Kurzbeschreibung
    • Features
    • Installation
    • Start
    • Bedienung
    • Projektstruktur
    • Beispielablauf
    • Bekannte Grenzen
    • Ausblick

    Nutze mindestens:

    • drei Überschriften
    • eine Liste
    • einen Codeblock
    • eine Tabelle
    • mindestens einen inline Code-Ausdruck wie python main.py
    Tipp

    Beschreibe nicht nur, was dein Projekt kann. Beschreibe auch, wie eine andere Person es starten kann.

    Lösung

    Beispielstruktur:

    ```markdown

    Flaggenquiz¶

    Eine kleine Quiz-App, in der Länder anhand ihrer Flaggen erraten werden.

    Features¶

    • zufällige Flaggen anzeigen
    • Antwort prüfen
    • Punktestand anzeigen

    Installation¶

    bash python -m venv .venv source .venv/bin/activate pip install -r requirements.txt

    Start¶

    bash python main.py

    Projektstruktur¶

    Datei Aufgabe
    main.py startet die App
    data.py enthält Länderinformationen

    Bekannte Grenzen¶

    • noch keine Highscore-Liste
    • noch keine Speicherung ```
    🌶 README-Review

    Tausche deine README mit einer anderen Person.

    Prüfe:

    • Ist klar, was das Projekt macht?
    • Ist klar, wie man es startet?
    • Gibt es einen Codeblock für Start oder Installation?
    • Gibt es eine Projektstruktur?
    • Gibt es bekannte Grenzen oder einen Ausblick?

    Schreibe danach drei konkrete Verbesserungsvorschläge.

    Lösung

    Beispiel für konkrete Verbesserungsvorschläge:

    • "Im Abschnitt Start fehlt der genaue Befehl python main.py."
    • "Die Datei data.py wird verwendet, aber in der Projektstruktur nicht erklärt."
    • "Der Abschnitt Features beschreibt nur ein Feature. Ergänze Punktestand und zufällige Fragen."
    🌶🌶 Installationsabschnitt schreiben

    Schreibe einen Markdown-Abschnitt ## Installation für ein Python-Projekt.

    Der Abschnitt soll diese Schritte enthalten:

    • Repository öffnen oder herunterladen
    • virtuelle Umgebung erstellen
    • virtuelle Umgebung aktivieren
    • Abhängigkeiten installieren
    • Programm starten

    Nutze mindestens zwei Codeblöcke.

    Lösung

    ```markdown

    Installation¶

    Öffne zuerst den Projektordner im Terminal.

    bash cd mein-projekt python -m venv .venv

    Aktiviere danach die virtuelle Umgebung:

    bash source .venv/bin/activate

    Installiere die Abhängigkeiten und starte das Programm:

    bash pip install -r requirements.txt python main.py ```
